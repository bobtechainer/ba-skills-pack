# Sample Bundle — Core Banking API Integration

**Fictitious project**: CoreLink API Integration — connecting a regional bank's legacy core banking system to a new digital banking layer.

**Purpose**: Demonstrates a complete 4-document bundle (Charter → BRD → SRS → HLD) generated from a single `facts.yml`.

## Bundle structure

```
sample-bundle/
  facts.yml           — Single source of truth for all numbers + names
  01_charter/         — Project Charter (PMBOK)
  02_brd/             — Business Requirements Document (IIBA BABOK)
  03_srs/             — Software Requirements Specification (IEEE 830)
  04_hld/             — High Level Design (TOGAF 4+1)
  _manifest.json      — Bundle metadata
```

## How to build

```bash
# Build all 4 docs with Techainer brand + fictitious client
node skills/document-suite/scripts/build_doc.js examples/sample-bundle/01_charter --brand techainer --client samplebank
node skills/document-suite/scripts/build_doc.js examples/sample-bundle/02_brd --brand techainer --client samplebank
node skills/document-suite/scripts/build_doc.js examples/sample-bundle/03_srs --brand techainer --client samplebank
node skills/document-suite/scripts/build_doc.js examples/sample-bundle/04_hld --brand techainer --client samplebank

# Generate cross-doc RTM
node skills/document-suite/scripts/generate_rtm.js examples/sample-bundle/

# Verify (no orphan requirements, no unresolved facts)
node skills/document-suite/scripts/verify_docs.js examples/sample-bundle/
```

## Cross-doc traceability

Business requirements (BRD) → Software requirements (SRS) → Design sections (HLD) → Test cases (Test Plan — not included in this sample).

The RTM (`RTM.csv`) is auto-generated by `generate_rtm.js` and must not be edited manually.
