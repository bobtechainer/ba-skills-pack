# Writing Standards

## Tone & Voice

- **Technical docs**: Precise, direct, no ambiguity. Third person.
- **Business docs**: Clear, action-oriented. Active voice. Second person where appropriate.
- **Proposals**: Confident but factual. Evidence over claims.
- **Reports**: Objective. Data first, interpretation second.

## Structure Rules

- Executive Summary / TL;DR first (for documents > 3 pages)
- Numbered sections for easy reference
- Tables for comparisons, metrics, requirements
- Bullet lists for 3+ parallel items
- Bold for key terms on first use only

## Language

- Vietnamese documents: Use technical terms in English (e.g., "deployment", "API", "database")
- Mixed audience: Vietnamese for business context, English for technical terms
- Define acronyms on first use

## Formatting

- Headings: No more than 3 levels (H1, H2, H3)
- Tables: Header row + consistent alignment
- Code: Inline `code` for commands/variables, fenced blocks for snippets
- Diagrams: Describe in text with notation for later rendering

## Quality Checklist

- [ ] Every section has substance (no filler)
- [ ] Data-backed claims have sources
- [ ] No orphaned acronyms (undefined abbreviations)
- [ ] Consistent terminology throughout
- [ ] Action items have owners and dates
